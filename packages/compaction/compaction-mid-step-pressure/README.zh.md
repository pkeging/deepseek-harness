# @deepseek-ai/dsh-compaction-mid-step-pressure

[English](README.md) | 中文

## 概要

基础压缩引擎在步骤边界处以及溢出报错之后检查上下文压力。一批并行工具调用是在两个边界**之间**完成的，因此这批结果进入持久请求时，没有任何压力检查能看到这次增长。本插件按 agent 统计已完成的工具结果数，当这一批达到配置的规模时，向压缩引擎索取一次 `pressure` 检查。

**挂载本插件本身就是开启**。不需要轮内检查的操作者，只需不把它写进组合，因此不涉及任何配置开关。

## 使用本包

把它挂在一个能解析轮内压力的压缩后端旁边：

```yaml
- name: '@deepseek-ai/dsh-compaction-basic'
- name: '@deepseek-ai/dsh-compaction-mid-step-pressure'
  config:
    threshold: 3
```

| 配置项 | 类型 | 默认值 | 作用 |
|---|---|---|---|
| `threshold` | 整数 ≥ 1 | `3` | 每个 agent 在触发一次压力检查前累计的已完成工具结果数。 |

`threshold` 设为 `1` 表示每个工具结果完成后都检查。调高它，用于覆盖"并行调用会使一轮增长超过一个步骤边界增量"的那个批量规模。

### 检查做了什么

插件调用引擎的 `compactIfNeeded(agent, 'pressure', signal)`——与引擎自身步骤边界监听器相同的入口。是否会因压力而真正压缩由引擎判断，不需要压缩时返回 `null`，因此上下文健康时这次检查很廉价。

计数器在检查运行时、以及 agent 报告 `idle` 时重置，所以一个批次不会跨越两轮。

不发布不变量伴生插件，因为本插件不拥有任何可供独立检查者观察的运行时关系：它的计数器是每个 agent 的私有状态，而一次检查触发的压缩可以通过引擎自身的事件观察到。

## 模型体验

### 轮内压缩时机

#### 模型看到的内容

本插件不提供任何提示词文本，也不提供任何工具声明。它对模型可见的全部作用在于时机：一旦已完成的工具结果达到 `threshold`，引擎就可以在这一轮内完成压缩，于是下一次请求已经带着原本要等到步骤边界检查才会产生的检查点。一次未发现压力的检查完全不改动该请求。

#### Token 影响

自身不产生 token。替换本身及其 token 削减属于压缩引擎；本插件只是把这一决策提前，模型读到的检查点前言与摘要格式都由引擎拥有。

#### KV Cache 影响

与本插件自身贡献无关——它不携带任何请求 token。一次返回且未真正压缩的检查会保留请求前缀可复用；当引擎确实替换了较早的一段历史时，该检查点会从第一个被替换的历史 token 起失效复用，与步骤边界压缩完全一致。

## 已知限制与暂缓事项

<a id="known-limitations-and-deferred-work"></a>

这些限制界定了轮内触发器何时会误判或静默；它们是本包当前的约束。

- **触发器统计的是工具结果数量，而非 token** —— 引擎级触发器若能对待处理结果定价、按实测溢出量压缩，会比这种启发式准确。
- **未配置压力策略的路由会在每次检查时告警** —— 引擎通过一个错误类报告该情况，而本包若要导入它就必须走深路径、源码面解析不到；静默跳过则会掩盖一处组合错误。
- **当前覆盖为桩压缩服务的行为测试** —— 挂载 `dsh-compaction-basic` 与回放模型、断言轮内压缩后对话记录的真实组合测试，尚未补齐。

### 开发备注

<details>
<summary>给维护者的工作上下文——点击展开</summary>

`ctx.compaction.compactIfNeeded` 在基类 `CompactionEngine` 上是公开的，`'pressure'` 也是公开的 `CompactionTrigger`。因此本触发器不需要任何引擎内部实现，得以位于 `compaction-basic` 之外，从而保持该后端不被修改。
