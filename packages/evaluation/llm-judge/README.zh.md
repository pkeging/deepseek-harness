# @deepseek-ai/dsh-llm-judge

[English](README.md) | 中文

LLM 即裁判评估工具。注册一个 `judge` 工具，接收目标、证据和评判标准，发起一次辅助模型调用，返回包含数值评分（1–10）、通过/失败判定和文本理由的结构化裁决。

本插件填补了 `tool-ralph` 缺失的评估器空白（其 README 明确标注完成状态为"工人自我声明"，没有独立验证）。裁判工具用于事后质量评估，或作为自定义工作流中的判定步骤——它不挂钩到 agent loop，也不改变工具路由。

## 契约

`judge({ objective, evidence, rubric })` 发起一次模型调用，携带固定系统提示和帧化用户提示（目标、评判标准、证据）。模型被指示仅返回有效 JSON。实现从响应中提取 JSON（裸 JSON、markdown 围栏 JSON，或长文本内的 `{…}` 片段），验证结构——`score` 必须是 1–10 的整数，`pass` 必须是布尔值，`reasoning` 必须是非空字符串——然后返回解析后的裁决。无效 JSON、非 JSON 响应或结构违规均以工具错误形式暴露（结果中 `isError: true`）。

## 配置

```yaml
- name: '@deepseek-ai/dsh-llm-judge'
  config:
    timeoutMs: 30000       # 每次调用截止时间；默认 30 000
    maxOutputTokens: 1024  # 裁判响应的输出上限；默认 1024
    provider: 'deepseek'   # 可选显式路由（须与 model 配对）
    model: 'deepseek-chat' # 可选显式模型（须与 provider 配对）
```

所有字段在插件加载时验证。缺少 `provider`/`model` 对时回退到 `deepseek`/`deepseek-chat`；部分配对时抛出。

## 模型体验

### 系统提示

#### 模型所见

judge 工具作为普通可调工具注册。其 schema 列出三个必填字符串参数（`objective`、`evidence`、`rubric`）和一个对象型输出（`score`、`pass`、`reasoning`）。系统提示中无额外引导——模型从工具描述和 schema 学习评估契约。

#### Token 影响

工具可见时每次请求产生固定的 schema 开销。

#### KV Cache 影响

工具定义和可见性不变时前缀稳定。

### 裁判调用

#### 模型所见

一次辅助请求，携带固定系统指令和帧化用户提示。提示要求仅返回 JSON 对象，包含目标、评判标准（完整长度）和证据（超过 4 000 字符时截断）。

#### Token 影响

每次调用一次辅助模型调用。`maxOutputTokens` 限制响应；默认 1024 对简短裁决绰绰有余。

#### KV Cache 影响

与父上下文独立——每次裁判调用都是全新分发。

## 已知限制与待办工作

- **单次调用** — 裁判发起单次模型请求；没有多轮辩论、没有 deliberation 回合、没有跨标准比较。
- **依赖 JSON** — 持续拒绝输出 JSON 或将裁决嵌入无解析性 `{…}` 片段的文本中的模型，会产生错误而非尽力裁决。
- **无法访问会话状态** — 工具仅接收调用者传入的三个字符串参数。它无法检查工作区、先前工具调用或 agent 自身的记忆。
- **评估器角色，非编排器** — 本插件不决定是否继续工作流；它仅返回裁决。将裁判输出与工作流控制结合是操作者的职责。
